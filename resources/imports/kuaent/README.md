# TestDocu documentation import

Source: user-provided `modules.rar`. The 203 Markdown files in 19 remaining
folders are preserved verbatim. Auth, Cart-Checkout, Catalog-products and
Catalog-rules-pricing are excluded because they were already entered manually.

After the GitHub FTP deployment finishes, open project **50 / TestDocu** on
Laratest and click **Import remaining modules** on its modules page.
The user must have both module and documentation creation permissions.
No migrations, server terminal commands, or local database changes are needed.

Each folder becomes a module; each file becomes one documentation entry,
with the filename (without `.md`) as its title. Markdown becomes formatted HTML
with tables, lists and code blocks. Raw HTML and unsafe links are filtered.
PDFs are generated by the existing download action when first requested.
New entries retain the normal `in_process` status and are attributed to the
signed-in user with a source record in worker history.

The importer validates source checksums before writing, checks project ID and
name, and runs all database writes in one transaction under a project lock.
Existing matching names/titles are skipped, including differences in case,
spaces and hyphens and document titles ending in `.md`. Existing contents are
never updated. Repeating the import adds no duplicate entries. Ambiguous module
names abort the import instead of choosing a module arbitrarily.

The four existing modules were unavailable locally, so their exact title
capitalization could not be inspected. The folder/file structure follows the
user's description. Project data will only change when the button is clicked
on the deployed application.
